Overview

Purpose of the project

  • Help users ask Quran-related questions in Arabic and receive a cited scholarly-style answer — not a free-form LLM guess.
  • Cover lookup of ayat آيات, tafsir تفسير, linguistics, asbab al-nuzool أسباب النزول, and surah statistics.
  • Orchestrate specialized agents so each step retrieves real data via Tafsir MCP, then compose an Arabic report: الإجابة + الأدلة.
Core mission: make Quranic AI answers retrievable, citable, and plan-driven.

Overview

Why it matters — grounded by Tafsir MCP

The risk

General LLMs invent Quranic wording, verse numbers, and tafsir attributions with high confidence.

  • Remote endpoint: https://mcp.tafsir.net/mcp · role-scoped tools for researchers.
  • Data & scientific stewardship: Tafsir Center for Qur’anic Studies · مركز تفسير للدراسات القرآنية (CC BY 4.0).

Overview

How it works — at a glance

Arabic question→ Plan→ Research Manager→ Research (parallel)→ Gap check→ Arabic report
  • Web UI (FastAPI) accepts the question and invokes the LangGraph.
  • Planner decides what evidence is needed — does not answer yet.
  • Research Manager is the sole router: dispatches parallel researchers, loops via Gap check, then finishes.
  • Researchers call Tafsir MCP tools until the plan is satisfied.
  • Report Generator writes الإجابة from collected evidence only.

System architecture · nodes

Node 1 · no tools

Planner

  • First node after START. Builds a minimal ResearchPlan.
  • Does not answer the user — only decides what evidence types and tasks are needed.
  • Sets flags: tafsir comparison, linguistic analysis, sabab nuzool سبب نزول.
  • Tasks map later to researchers (fetch_ayah, tafsir_fetch, linguistic, nuzool, …).
Plan-first principle starts here: investigate before generating an answer.

System architecture · nodes

Node 2 · sole router · no tools

Research Manager

  • The only router for next work after planning.
  • Collects dependency-ready tasks → maps kind → researcher actions.
  • Can dispatch a parallel wave of multiple researchers in one decision.
  • Gates specialty research until selected_verses exist.
  • Chooses: research wave · gap analysis · optional comparison · finish (report).

System architecture · nodes

Node 3 · MCP tools

Quran Researcher

  • Retrieves Quran text and meta via MCP — not from model memory.
  • Tools: search_quran_text, fetch_ayah, fetch_surah_info, overview, statistics.
  • Fills discovered_verses / selected_verses and citation evidence.
  • Always edges to Gap Analyzer after running.

System architecture · nodes

Node 4 · MCP tools

Tafsir Researcher

  • Runs only when the plan requires classical commentary.
  • Tools: fetch_tafsir, search_in_tafsir, list sources for an ayah آية.
  • Produces attributed TafsirEvidence (source id, author, text).
  • Waits for selected verses before the Manager dispatches it.

System architecture · nodes

Linguistic & Context researchers

Linguistic Researcher · Node 5

Word/root study when planned. Tools: analyze_word, find_root_occurrences, get_root_stats.

Context Researcher · Node 6

Asbab al-nuzool أسباب النزول when planned. Tools: fetch_nuzool_reason, source lists.

Both are MCP tool agents; both join at Gap Analyzer; both are verse-gated by the Manager.

System architecture · nodes

Node 7 · deterministic · no tools

Gap Analyzer

  • Compares the plan (required evidence types / flags) to what was collected.
  • May append recommended tasks into the plan if something is missing.
  • Sets gap_status (insufficient / sufficient) and iteration counters.
  • Always returns to Research Manager — Manager decides loop / compare / finish.
Sufficiency is code-checked — not “the LLM feels done.”

System architecture · nodes

Tafsir Comparator & Report Generator

Tafsir Comparator · Node 8

Optional. Only if Manager chooses comparison. Contrasts mufassirs using collected tafsir evidence.

Report Generator · Node 9

Final Arabic الإجابة + الأدلة. Must cite exact evidence labels — then END.

System architecture · MCP

Tafsir MCP component

  • Remote Streamable HTTP endpoint (default https://mcp.tafsir.net/mcp).
  • Wrapped as LangChain tools in mcp/client.py.
  • Role toolsets in mcp/toolsets.py — each researcher sees only its tools.
  • assert_tool_allowed enforces boundaries at call time.

Design considerations

How we keep research
grounded & efficient

Plan first · Parallel execution · Hallucination guards

Consideration 1

Plan first — then execute

  • The Planner commits to a ResearchPlan before any researcher runs.
  • Graph wiring: START → planner → research_manager — no skip path.
  • Minimal tasks only — avoid fetching tafsir when the question does not need interpretation.
  • Gap Analyzer later checks that same plan — the contract for “done.”
Planning separates what to investigate from generating an answer — reducing premature hallucination.

Consideration 2

Parallel execution

  • Manager emits multiple ResearchDispatch entries in one wave.
  • route_after_research_manager returns a list of nodes → LangGraph fan-out.
  • Quran / Tafsir / Linguistic / Context can run together when dependencies allow.
  • All join at Gap Analyzer, then loop back to Manager.
Parallel waves cut latency when several evidence types are needed — with one join point for sufficiency.

Consideration 3

Hallucination guard mechanisms

  • Tool-grounded evidence — findings from MCP results, not free-form recall.
  • Role-scoped tools — researchers cannot call out-of-role tools.
  • Citation-bound report — exact citation labels in الأدلة.
  • Deterministic gap check — plan vs evidence in code.
  • Append-only evidence + max iterations (default 3).
  • Grounded comparator — uses collected tafsir only.
Layered guards: retrieve → scope → verify → cite.
